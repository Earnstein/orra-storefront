# M6 Store Admin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner runs the store from `/admin`; any visitor can try the same admin through a shared demo account, edit a product and see it on the storefront; every night the demo goes back to its seed.

**Architecture:**
- **Roles:** Better Auth's `admin` plugin with access control (roles `admin`, `demo-admin`, `user`) and a server-side `requireAdmin(permission)` in front of every admin page, route and action.
- **Admin screens:** under `/admin`, with their own header. TanStack Table v9 lists over private admin API routes (TanStack Query, nuqs for table state) and TanStack Form editors over server actions that call `updateTag("catalog")`.
- **Demo:** a demo account signed in by a rate-limited route, and a nightly, secret-protected reset route (Vercel Cron) that re-seeds the catalogue.

**Tech Stack:** Next.js 16.3 (Cache Components), Better Auth 1.7.7 (`admin` plugin, access control), Drizzle on Neon (PGlite in tests), TanStack Table 9, Query 5 and Form 1, nuqs, shadcn on Base UI, Vercel Blob (`@vercel/blob`, new), Vercel Cron, Vitest, Playwright with axe.

**Spec:** `docs/superpowers/specs/2026-10-18-m6-admin-design.md`

- **Dependencies:**
  - `@vercel/blob`, exact version, latest stable at install, checked for maintenance and size.

## Review Focus

1. **The demo admin reaching further than allowed:** a demo session calls Better Auth's admin endpoints (list users, set its own role, impersonate, revoke sessions), our owner-only actions (fulfil, cancel), or asks for unmasked order details. Expected: 403 and no change, every time, on the server. *Pinned in Tasks 2, 8 and 10.*
2. **An archived product still in use:** it's in a bag, a held checkout, an order, saved items or a story. Expected:
   - the bag shows "No longer available" outside the count;
   - checkout won't hold it;
   - existing holds and orders keep working;
   - its page and listings drop it;
   - the editorial pages skip it rather than breaking;
   - the reset handles it.

   *Pinned in Tasks 4 and 11.*
3. **Slug edits:**
   - Changing a product's slug to one that exists → refused with a field error.
   - Changing the slug of a product that stories or landings reference (`src/content/`) → refused, since the content would break.
   - Changing the slug of a product in someone's bag or saved items → those follow the product (they key on the id). Old links 404.

   *Pinned in Task 5.*
4. **Editing stock while units are held:**
   - The stock field is "available now": it doesn't include units in open holds, and the form shows "N more held in checkouts".
   - Saving can't push stock below zero or under a concurrent sale. The update writes the new value only if stock hasn't changed since the form loaded, and otherwise asks to reload.

   *Pinned in Task 5.*
5. **The reset running mid-checkout:** an open hold on a seed product when the reset restores stock. Expected: the restored stock is the seed's value minus units still in open holds, so releasing the hold later doesn't push it above the seed. The open hold, its payment and any order it becomes keep working. *Pinned in Task 11.*
