# M4 Accounts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Visitors can sign up, sign in, reset a password and manage their account, and saved items follow a signed-in shopper to every device, while signed-out behaviour and page caching stay as in `v0.4.0`.

**Architecture:**
- **Settings:** Better Auth's options grow in `auth.options.ts` (password rules, sessions, database-backed rate limits, reset email, deletion).
- **Signed-in state:** pages stay static, and the session is read in the browser.
- **Saved items:** signed out, they stay in localStorage; signed in, they come from a private endpoint and change through server actions with optimistic TanStack Query updates.
- **Server-side session checks:** only `/account` pages, server actions and route handlers read the session on the server.

**Tech Stack:** Next.js 16.3 (Cache Components), Better Auth 1.7.7, Drizzle on Neon (PGlite in tests), TanStack Query 5 and Form 1, shadcn on Base UI, Resend, Vitest, Playwright with axe.

**Spec:** `docs/superpowers/specs/2026-10-06-m4-accounts-design.md`

## Global Constraints

- **Process (as in M1–M3):**
  - npm only. One module = one branch = one PR, assigned to the GitHub Milestone `M4 · Accounts`, with the PR template completed.
  - The user approves by squash-merging; never merge. Every `git push` needs the user's approval.
  - Stage files by path; never `git add -A`. No attribution anywhere (no Co-Authored-By, no "Generated with").
  - Run a fresh-context review subagent (opus) over each branch before its PR. Fix Critical and Important findings, and record the minors in `.superpowers/sdd/2026-10-06-m4-accounts/progress.md`.
  - After `gh pr create`, call ccd_pr `get_status` once. Never poll CI.
- **Production safety:**
  - Never read `.env` or `.env.local`; worktrees symlink both.
  - Before any local `db:migrate`, `npm run db:seed -- --check` must print `not production`.
  - Local database, build and e2e runs use `NODE_OPTIONS="--dns-result-order=ipv4first --no-network-family-autoselection"`.
- **Migrations:**
  - Auth tables come from `npm run auth:generate`, never hand-edited.
  - Generate migrations with `npm run db:generate -- --name <name>`.
- **Dependencies:** `resend` (module 2, exact version, latest stable at install). shadcn adds `dropdown-menu` and `alert-dialog` when needed. Nothing else new without asking.
- **Auth values (from the spec):**
  - Passwords are 8–128 characters.
  - Sessions last 30 days (`expiresIn: 60 * 60 * 24 * 30`), with `rememberMe: false` when "Stay signed in" is off.
  - The cookie cache is on, with `maxAge: 300`. Browser session reads may accept a revoked session for up to 5 minutes; `getCurrentUser` skips the cache, so server-side checks refuse it at once.
  - Reset tokens last `3600` seconds, and a reset revokes all sessions.
  - `user.deleteUser.enabled: true`. Email verification is not required.
- **Rate limits:** `storage: "database"`, on only when `VERCEL_ENV` is `production` or `preview`.

  | Path | Limit |
  |---|---|
  | `/sign-in/email` | 5 per 60 s |
  | `/sign-up/email` | 3 per 60 s |
  | `/request-password-reset` | 3 per 900 s |

- **Saved items:** at most 200 per account and per request. Slugs match `^[a-z0-9]+(?:-[a-z0-9]+)*$` and are at most 100 characters.
- **Copy:** fixed by the spec. In particular:
  - "That email and password don't match."
  - "If an account exists for that email, we've sent a link."
  - "Your password has been changed. Sign in with your new password."
  - "Your account has been deleted"
  - "Sign in to keep your saved items on every device"
  - "You haven't saved anything yet"
- **UI:**
  - Use the existing tokens, primitives and type roles. Forms use TanStack Form plus shadcn `Field`; use the Base UI `render` prop, not `asChild`.
  - Browser-check at 375, 1024, 1280 and 1440 px with no overflow and no console errors other than known 404 prefetches.
  - `/sign-in*`, `/account` and `/saved` are `noindex`.
- **e2e:**
  - Follow the conventions in `CLAUDE.md` (`gotoHydrated`, no `load` waits).
  - Tests that create accounts are tagged `@writes`. Each signs up a fresh `…@example.test` user and deletes it at the end.

## Review Focus

1. **Hostile `returnTo`:** `//evil.com`, `https://evil.com`, `/\evil.com`, `javascript:`, `/sign-in?returnTo=/sign-in`, empty or very long values. Expected: fall back to `/account`; never leave the site or loop. *Pinned in Task 6.*
2. **Rapid Save toggles** on a slow network. Expected: the final state matches the last click on screen and on the server; a failed action rolls back. *Pinned in Task 16.*
3. **The session ending while on `/account`** (signed out in another tab, or revoked from another device). Expected: the next account action answers "signed out" and goes to `/sign-in?returnTo=/account`; nothing crashes. *Pinned in Task 11.*
4. **Merging odd lists:** unknown or deleted products, duplicates, more than 200 in the browser, a nearly full account, and items already in the account. Expected: unknown ones are skipped, the account never exceeds 200 and a merge never removes its items, items that don't fit stay in the browser, and nothing errors. *Pinned in Task 15.*
5. **Two tabs at sign-in,** both holding browser saved items. Expected: the merge is idempotent, no duplicates, and merged items leave the browser's list after success. *Pinned in Tasks 15 and 16.*
