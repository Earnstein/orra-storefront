# M3 Find Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every listing can be filtered, sorted and paged through the URL, and search finds products as the shopper types (typos included), in a header panel and on `/search`.

**Architecture:**
- **Caching.** Next 16 Cache Components: catalogue reads are `"use cache"` functions tagged `catalog` with a 5-minute lifetime. Route segment configs go.
- **Search.** A trigger-maintained `tsvector` plus `pg_trgm` in Postgres. One pure query builder, and one cached `getResults` that returns products, a total and facet counts.
- **URL and client.** nuqs parsers shared by pages, endpoints and client. Two cached JSON endpoints. TanStack Query (`useInfiniteQuery`) on the client, hydrated from the server's first page. Pacer debounces the search text.

**Tech Stack:** Next.js 16.3 (Cache Components), React 19.2, Drizzle 0.45 + drizzle-kit 0.31, Neon, Postgres FTS + `pg_trgm`, nuqs 2.10.1, TanStack Query 5.104, TanStack Pacer 0.24.1, shadcn on Base UI, Vitest 5 + PGlite 0.5.8, Playwright 1.63 + @axe-core/playwright 4.13.0.

**Spec:** `docs/superpowers/specs/2026-10-05-m3-find-design.md`. Roadmap: `docs/superpowers/specs/2026-10-04-roadmap-to-live-design.md`. Read both.

**Rulings vs the spec** (sequencing only; confirm when reviewing the plan):
- The empty-state e2e fix carried from M2 moves to module 5 (Task 13), because it needs `/search`.
- `completeRows()` moves from the editorial product row to `src/components/product/complete-rows.ts` (Task 10), so the related-products row can share it.

## Global Constraints

- **Process (as in M1 and M2):**
  - npm only. One module = one branch = one PR, assigned to the GitHub Milestone `M3 · Find`, with the PR template completed.
  - The user approves by squash-merging; never merge. Every `git push` needs the user's approval.
  - Stage files by path; never `git add -A`. No attribution anywhere.
  - Run a fresh-context review subagent (opus) over each branch before its PR. Fix Critical and Important findings, and ledger the minors in `.superpowers/sdd/2026-10-05-m3-find/progress.md`.
  - After `gh pr create`, call ccd_pr `get_status` once. Never poll CI.
- **Production safety:**
  - Never read `.env` or `.env.local`; worktrees symlink both.
  - Before any local `db:migrate`, `npm run db:seed -- --check` must print `not production`.
  - Local database, build and e2e runs use `NODE_OPTIONS="--dns-result-order=ipv4first --no-network-family-autoselection"`.
- **Migrations:**
  - Generate with `npm run db:generate -- --name <name>`; edit by hand only to add triggers and backfill.
  - Production is migrated, never re-seeded, so every new column is backfilled in its migration.
- **Dependencies:** exact versions `nuqs@2.10.1`, `@tanstack/react-pacer@0.24.1`, `@axe-core/playwright@4.13.0` (dev). Nothing else new without asking.
- **Caching:**
  - No `export const revalidate` or `export const dynamicParams` anywhere after Task 2.
  - Catalogue reads use `"use cache"`, `cacheTag("catalog")` and `cacheLife("catalog")`.
  - The `catalog` profile is `{ stale: 300, revalidate: 300, expire: 3600 }`.
- **Search values (from the spec):**
  - `q` is capped at 100 characters, and the last word matches as a prefix.
  - Trigram matching uses `<%` at pg_trgm's default threshold.
  - Pages hold 24 products.
  - Price bands: `under-500` (< 50000), `500-1000` (50000–99999), `1000-2000` (100000–199999), `2000-plus` (≥ 200000).
  - The panel shows up to 6 products, debounced 200 ms, from 2 characters.
- **URL keys:** `q`, `sort`, `category`, `audience`, `colour`, `material`, `price`, `stock` (`in`), `new` (`1`), `page`.
  - Sort values: `newest`, `price-asc`, `price-desc`, `relevance` (`/search` only).
- **History:** sheet "Show N items" and chip removal **push**; Load more and the `/search` query field **replace**; all updates are shallow.
- **UI:**
  - Use the existing tokens, primitives and type roles, and shadcn components on Base UI (`render` prop, not `asChild`).
  - Browser-check at 375, 1024, 1280 and 1440 px with no overflow and no console errors other than the known 404 prefetches.
- **Performance budgets** (recorded in the PRs from module 3 on, measured on the Vercel preview):
  - endpoints < 50 ms server time when cached, < 150 ms uncached;
  - search results < 300 ms after the last keystroke;
  - listing LCP no worse than M2's.
- **Copy:** original. Gucci UK is a pattern reference only.

## Review Focus

1. **Hostile or odd search text:** quotes, `&|!:*()`, SQL fragments, only punctuation, emoji, 500 characters. Expected: never a 500; punctuation-only behaves like an empty query. *Pinned in Task 4 (builder) and Tasks 7 and 11 (endpoints).*
2. **Hand-edited or stale URLs:** unknown filter values, `page=0`, `page=-3`, a page past the end, `sort=relevance` on a listing, repeated keys. Expected: invalid values are dropped, the page is clamped, the response is 200 with sensible results. *Pinned in Task 6 (parsers) and Task 7 (endpoint).*
3. **Changing filters faster than responses arrive.** Expected: the latest state wins; an older response never overwrites newer results. *Pinned in Task 9's e2e test (two quick changes, then the final URL, count and grid agree).*
4. **Back, forward and reload after filters and Load more.** Expected: each lands on the same state it left. *Pinned in Tasks 8 and 9's e2e tests.*
5. **A selected option whose count is 0, or a result set of 24 or fewer.** Expected: the selected option stays enabled so it can be removed; the empty state offers Clear all; Load more is hidden when everything is shown. *Pinned in Task 8 (Load more hidden) and Task 9 (`optionState`).*
