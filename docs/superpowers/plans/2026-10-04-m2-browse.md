# M2 Browse Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every primary-nav link opens a working page — collection listings and the Women/Men landing pages. The catalogue grows to 48 products carrying audience, colour family and material. Stories and the 404/error pages exist.

**Architecture:**
- **Listings.** One pure resolver maps `/collections/<slug>[/<category>]` to a scope: new arrivals, an audience, or a category. One query returns that scope's products. The pages stay ISR.
- **New fields.** They arrive through hand-edited Drizzle migrations that backfill today's 9 products, so production (migrated, never seeded by builds) stays valid.
- **Editorial pages.** These are typed block lists in `src/content/`. A server-component renderer loads each page's products in a single query.

**Tech Stack:** Next.js 16.3 (App Router, ISR), Drizzle 0.45 + drizzle-kit 0.31 (pg enums, migrations), Neon, Vitest 5 + PGlite 0.5, Playwright 1.63, `tsx`, Unsplash (free licence), `gh` CLI.

**Spec:** `docs/superpowers/specs/2026-10-04-m2-browse-design.md`. Roadmap: `docs/superpowers/specs/2026-10-04-roadmap-to-live-design.md`. Read both.

**Rulings vs the spec** (sequencing only; the user is asked to confirm these when reviewing the plan):
- **The seed guard moves from module 3 to module 2** (Task 3). It has to exist before the first local `db:migrate`/`db:seed`. It gains a `--check` flag that reports whether the target database is production, without connecting.
- **Module 4 is split into two PRs.** `feat/editorial-stories` (block system + stories) comes first, because the landing pages link to a story. `feat/editorial-landings` follows.

## Global Constraints

- **Process (as in M1):**
  - npm only; Node 24 in CI; no `@vitejs/plugin-react`.
  - One module = one branch = one PR, assigned to the GitHub Milestone `M2 · Browse`, with the PR template completed.
  - The user approves by squash-merging; never merge. Every `git push` needs the user's approval.
  - Stage files by path; never `git add -A`.
  - No attribution anywhere: no `Co-Authored-By`, "generated with" or watermarks.
- **Production is never touched from local work.**
  - From Task 3 on, local database commands target the Neon `dev` branch through `.env.local`.
  - Never read `.env` or `.env.local`; worktrees symlink them.
  - Before any local `npm run db:migrate`, run `npm run db:seed -- --check`. It must print `not production`.
- **Production builds migrate but never seed.** The only production seed is Task 7's release step, run by the user with `--production`.
- **Migrations:**
  - Generate with `npm run db:generate -- --name <name>`, edit by hand only to add a backfill, and apply with `db:migrate`. Never `db:push`.
  - Each migration that adds a required column follows the same pattern: add it nullable → backfill by slug → set `NOT NULL`.
- **Enum values, exactly:**
  - `audience`: `women`, `men`, `unisex`.
  - `colour_family`: `black`, `white`, `grey`, `beige`, `brown`, `red`, `pink`, `orange`, `yellow`, `green`, `blue`, `purple`, `gold`, `silver`, `multicolour`.
  - `material`: `leather`, `suede`, `canvas`, `nylon`, `cotton`, `linen`, `wool`, `cashmere`, `silk`, `satin`, `gold`, `silver`, `metal`, `acetate`, `mixed`.
- **Backfill for today's 9,** as `slug: audience / colour family / material`:
  - `top-handle-bag-teal`: women / green / leather
  - `double-monk-shoe`: men / brown / leather
  - `round-sunglasses`: unisex / gold / metal
  - `gold-hoop-earrings`: women / gold / gold
  - `leather-biker-jacket`: unisex / black / leather
  - `bomber-jacket-rust`: men / orange / nylon
  - `floral-pump`: women / blue / satin
  - `fringed-knit-poncho`: women / beige / cotton
  - `leather-tote-tan`: unisex / brown / leather

  Any other row gets `unisex` / `multicolour` / `mixed`.
- **Catalogue (Task 7 pins these in tests):**
  - 48 products: bags 10, shoes 10, accessories 10, jewellery 8, ready-to-wear 10.
  - Audience: women 24, men 16, unisex 8.
  - Prices 25,000–350,000 cents.
  - Exactly 3 sold out (stock 0) and exactly 5 low (stock 1–3).
  - Today's 9 stay first in the seed, in today's order.
- **Images:**
  - Free Unsplash only. Image URLs are on `images.unsplash.com`; Unsplash+ (`plus.unsplash.com`) is never used.
  - Bare `https://images.unsplash.com/photo-<id>`, or `gallery()` crops.
  - Each photo is checked at full size for logos and brand marks. Every image has alt text.
  - The user approves a contact sheet before any new photo is used.
- **Copy:** original writing; no brand names; no text taken from other sites. Gucci UK is a pattern reference only.
- **Reserved collection slugs:** `new`, `women`, `men`.
- **UI:**
  - Use only the existing primitives, type roles and tokens.
  - Check the browser at 375, 1024, 1280 and 1440 px, measuring spacing with `getBoundingClientRect` against the tokens. No console errors.
  - Listings and editorial pages are ISR, `revalidate = 300`.

## Review Focus

1. **The backfill migrations meet real rows.** Production, and every preview or CI branch copied from it, already holds the 9 products. Expected: each migration succeeds and fills in every value; an unknown row gets the fallback. *Pinned in Task 4 (and extended in Task 6) by a test that applies the migrations in two steps, with pre-M2 rows inserted in between.*
2. **A local database command runs without `.env.local`**, for example in a fresh worktree, and so falls through to production. Expected: `db:seed` refuses unless `--production` is passed, and `--check` names the target. *Pinned in Task 3's guard tests and its `--check` verification against `.env` alone.*
3. **Editorial content references something that doesn't exist:** a product, category, story or route that is mistyped or renamed later. Expected: CI fails with a readable list of problems. *Pinned in Task 8 (`findContentProblems`), with Tasks 9 and 10 running it over their content.*
4. **A known collection or tab has no products, or the path is unknown.** Expected: a known but empty collection returns 200 with the empty state; an unknown path returns 404. *Pinned in Task 5 by a query test on an empty category and e2e 404 cases.*
5. **Narrow phones and long names on the new pages** (tabs, tiles, product rows, stories). Expected: no horizontal overflow at 375 px. *Pinned in Tasks 2, 5, 9 and 10, which add each new page to the overflow test.*
