# M7 Launch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** finish the demo for `v1.0.0`: monitoring and analytics, honest help and legal pages with no dead links, SEO files, launch checks in CI, the case study, and the release.

**Architecture:** content pages are typed data in `src/content/` rendered by two static routes; SEO uses Next's metadata files (`sitemap.ts`, `robots.ts`) and `metadataBase`; the quality gates are Playwright specs plus a Lighthouse CI step in the existing e2e job; monitoring hooks in through `instrumentation.ts`.

**Tech Stack:** Next.js 16.3 (Cache Components, Turbopack), `@sentry/nextjs` 11 (server only), `@vercel/analytics` 2, Playwright + `@axe-core/playwright`, `@lhci/cli` 0.15, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-30-m7-launch-design.md`

## Global Constraints

- No custom domain: production is `https://orra-storefront.vercel.app`; emails stay on Resend's test sender.
- Free tiers only; no consent banner, so nothing non-essential is stored on the visitor's device.
- Storefront JavaScript: `v0.7.0` plus monitoring and analytics, within the spec's limit; LCP no worse than `v0.7.0`.
- New content pages are static and add no client JavaScript of their own.
- Copy says only true things about a demo; no "until M7" or "until launch".
- One module = one branch = one PR in milestone "M7 · Launch"; every push needs the user's approval; stage by path; no attribution lines.
- Never read `.env` or `.env.local`; no secret-lookalike strings in code or tests.

## Review Focus

1. **A link added later to a page that doesn't exist** (header, footer, content): the unit check over `site.ts` and the e2e link check must both fail. Task 5 and Task 9 pin it.
2. **Archived products in the sitemap:** an archived product must not be listed. Task 7 pins it.
3. **`robots.txt` on a preview** must disallow everything, even though previews are behind the login. Task 7 pins it.
4. **Personal data in error reports:** an error message containing an email address, or a failed form action, must not send the address or the form values. Task 2 pins it.
5. **A canonical URL carrying filters or a guest order key:** canonicals are path-only, and `/orders/*` stays `noindex`. Task 6 pins it.
